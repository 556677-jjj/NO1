# 第六章：个人 AI 系统建设

> 一句话目标：把零散的聊天、文件和经验，慢慢变成一个能查找、能更新、能长期使用的个人资料系统。
> 内容核对日期：2026-11-07

## 一、为什么需要自己的资料系统？

你可能遇到过这些情况：
- 上个月问过 AI 的问题，现在找不到答案。
- 一份软件操作说明散落在聊天记录和截图里。
- 学过一门课程，却没有留下完整笔记。
- 同一个问题反复问，重复花时间。
- 资料越来越多，却不知道应该放在哪里。

这不是因为你记性不好，而是缺少一个固定的保存和整理方法。

**个人资料系统的目标很简单：重要的东西有地方放，未来的自己找得到，也知道它是否过时。**

## 二、让不同工具各司其职

可以用一个简单的比喻：
- **ChatGPT 等助手：讨论和整理的工作台。** 帮你分析、解释、写草稿、制定计划。
- **Codex 等执行工具：动手的工作人员。** 在获得授权的环境中处理项目文件、代码和多步骤任务。
- **GitHub：长期资料柜和修改记录本。** 保存文件、分类、查看历史变化。
- **你本人：最终负责人。** 决定什么重要、什么可以公开、哪些修改值得保留。

不要把聊天记录当成唯一备份，也不要把 GitHub 当成密码保险箱。

## 三、建立简单、稳定的分类

你的 NO1 仓库已经采用了以下分类：

| 分类 | 适合保存什么 |
|---|---|
| 01-AI工具 | AI 产品说明、使用经验、提示模板 |
| 02-电脑软件 | Windows 软件、安装、设置和故障处理 |
| 03-手机应用 | 手机 App、权限、设置和使用方法 |
| 04-学习资料 | 课程、书籍、视频和学习笔记 |
| 05-个人生活 | 日常计划、生活经验和非敏感资料 |
| 06-GitHub优秀项目收藏 | 值得进一步了解的开源项目 |

分类不必追求一次设计完美。以后发现某类资料太多，再增加子目录即可。

## 四、每份资料尽量使用统一格式

建议普通说明文档都包含：
1. **标题**：这份资料解决什么问题？
2. **用途**：什么时候需要它？
3. **适用范围**：软件版本、设备或日期。
4. **主要内容**：步骤、知识点或经验。
5. **注意事项**：风险和容易出错的地方。
6. **来源**：官方链接或原始资料。
7. **核对日期**：最后一次确认是什么时候。
8. **状态**：已验证、待测试、已过时或需要更新。

例如，一份 Windows 软件安装指南，应该标出软件版本和核对日期。半年后软件界面变了，就能知道这份指南可能需要复查。

## 五、建立简单的资料处理流程

每当你遇到有价值的资料，可以这样做：

<box border radius="lg" padding={3} gap={2}>
  <list connector="solid" marker="number" gap={2}>
    <list-item>**收集**：保存原始链接、文件或截图。</list-item>
    <list-item>**判断**：这份资料属于哪个分类？是否值得长期保存？</list-item>
    <list-item>**整理**：让 AI 提炼重点，补充标题和使用说明。</list-item>
    <list-item>**核对**：确认来源、事实和适用范围。</list-item>
    <list-item>**归档**：保存到对应目录，更新索引。</list-item>
    <list-item>**复用**：以后遇到类似问题，先查已有资料再继续补充。</list-item>
  </list>
</box>

这样可以避免资料只是“存起来”，却从来没有真正被使用。

## 六、GitHub 对普通人有什么用？

GitHub 最有价值的地方，不只是存文件，而是能记录每次修改。

例如：
- 今天新增一份软件安装指南。
- 下个月发现步骤有变化，更新说明。
- 以后需要时，可以查看历史版本，知道以前写过什么。

对非程序员来说，可以把它理解为一个带有修改历史的资料库。你不必先学会编程，才可以保存 Markdown 文档和普通项目资料。

不过，私有仓库也不等于绝对安全。不要保存密码、验证码、私钥、完整身份证件或银行卡信息。给第三方工具授权时，也要检查授权范围。

## 七、建立文件命名规则

建议使用“编号-主题-必要版本或日期”的方式。

例子：
- 01-ChatGPT基础使用.md
- 02-Windows软件安装指南.md
- 03-手机应用权限说明.md
- 2026-11-07-课程学习总结.md

命名原则：
- 一眼看出文件讲什么。
- 同一主题尽量保持统一写法。
- 版本或日期只在确实有帮助时加入。
- 避免使用“新建文档”“最终版2”“最新最新”等模糊名称。

## 八、怎样避免资料越积越乱？

### 不要什么都保存
只保存未来可能再次使用、对你有帮助的内容。临时闲聊、重复内容和无可靠来源的传言，不必都进入知识库。

### 不要只保存 AI 的总结
重要资料尽量保留原始来源链接。总结方便阅读，原始来源方便以后核实。

### 不要随意覆盖旧文件
更新重要指南前，先确认内容和修改范围。可以在文档里记录更新日期和变更摘要，GitHub 也会保留提交历史。

### 不要把私人资料误放到公开位置
确认仓库是 Private。分享文件或开放权限前，检查文件里是否包含个人信息、密钥或不应公开的内容。

### 不要假设 AI 能永久记住所有事情
重要约定、文件路径和项目进度应写入项目说明或 README。不要只依赖聊天记忆。

## 九、给 NO1 仓库建立日常维护规则

建议今后新增资料时，遵守以下约定：
- 新资料先判断分类，再创建文件。
- 尽量新建文件，不随意删除旧资料。
- 更新已有文件前先读取当前版本。
- 修改后检查文件是否保存成功。
- 更新目录和索引。
- 对未经实际测试的操作标记“待测试”。
- 记录资料来源和核对日期。
- 不保存密码、验证码、银行卡号、身份证号码和私钥。
- 有重大结构变化时，先向仓库所有者说明并征求确认。

## 十、可以直接复制的资料归档指令

> 请帮我整理这份资料，并准备保存到我的个人知识库。
> 先判断它属于哪个分类，并说明理由。
> 请整理成通俗易懂的中文文档，包含：标题、用途、核心内容、实际案例、注意事项、来源和核对日期。
> 不要编造原资料没有的信息；补充内容请单独标明。
> 如果已有同主题文件，请先检查是否适合补充，避免重复创建。
> 不要删除旧资料，也不要覆盖重要内容。
> 保存后请检查文件是否存在、内容是否完整、目录链接是否正确，并告诉我实际完成了哪些操作。

## 十一、怎样让知识库真正产生价值？

资料库不是收藏比赛。真正有价值的是你能在需要时把它用起来。

可以从三个习惯开始：
- **遇到问题先搜索**：先看看知识库里是否已经有解决办法。
- **解决后留下经验**：把确认有效的方法补充进去。
- **定期检查过时内容**：尤其是软件版本、价格、政策和产品功能。

例如，你之前解决了某个 Windows 软件的安装问题。下一次遇到类似情况，就先查自己的操作指南，不必从头问起。

## 十二、本章动手练习

选择一个你已经有一些资料的主题，例如“电脑软件”或“手机应用”：
1. 找出三份相关资料。
2. 为它们确定分类和文件名。
3. 让 AI 按统一格式整理。
4. 检查来源、版本和核对日期。
5. 保存到对应目录。
6. 更新目录索引。
7. 试着从目录重新找到其中一份资料。

如果能在短时间内找到并理解这份资料，说明你的系统开始发挥作用了。

## 十三、本章小结

- 个人知识库的目的，是让资料未来能找到、能理解、能更新。
- 助手负责分析整理，执行工具负责授权范围内的操作，GitHub 负责长期保存和版本记录。
- 分类和命名越简单稳定，越容易坚持。
- 保留来源、版本和核对日期，能减少过时信息带来的问题。
- 不保存密码、验证码和其他高度敏感信息。
- 资料库要不断被使用和更新，才会真正有价值。

**最重要的一句话：不要只让 AI 帮你解决今天的问题，还要把有用的解决办法留下来，帮助未来的自己。**
