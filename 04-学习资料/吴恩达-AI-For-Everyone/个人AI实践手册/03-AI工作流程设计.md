# 第三章：AI 工作流程设计

> 一句话目标：学会把一件复杂的事拆成清楚的小任务，让 AI 从“回答问题”进一步帮你完成工作。  
> 面向读者：没有编程基础、希望把 AI 用在学习、工作和生活中的普通用户。  
> 内容核对日期：2026-11-07

## 一、为什么 AI 有时回答得很好，却没有把事情做好？

想象一下，你对一位刚来上班的同事说：

“帮我把公司的资料整理好。”

这句话听起来很清楚，但同事一定会有很多疑问：

- 哪些资料？
- 按什么分类？
- 文件要放在哪里？
- 重复文件怎么处理？
- 要不要修改原文？
- 什么样才算整理完成？

AI 也一样。你给它的要求越模糊，它就越需要猜。猜得越多，结果越容易和你的想法不一样。

**真正有效的做法：不要只告诉 AI 你想做什么，还要告诉它为什么做、有什么资料、有哪些限制，以及怎样才算完成。**

## 二、把 AI 当成一位新同事，而不是一个会读心的人

安排任务时，可以用下面六个部分：

1. **目标**：最后想得到什么？
2. **背景**：为什么要做这件事？给谁使用？
3. **现有资料**：你已经有哪些文件、截图、链接或信息？
4. **限制**：哪些事情不能做？有哪些条件必须遵守？
5. **完成标准**：怎样才算做好？
6. **交付方式**：最终结果放在哪里、用什么格式交给你？

### 一个生活例子：整理家庭旅行资料

不够清楚的说法：

“帮我安排一次旅行。”

更清楚的说法：

“我想安排一次三天两晚的家庭旅行，同行有两位老人。希望每天不要太赶，优先考虑交通方便、步行少的景点。请先给我一份行程草案，列出每天的景点、交通方式、预计花费和需要提前预约的项目。价格和开放时间请查官方来源，暂时不要替我付款或预订。最后用表格整理，并标出还需要我确认的事项。”

你会发现，第二种要求更容易得到能用的结果。

## 三、复杂任务不要一次塞给 AI，要分成几个阶段

一项复杂工作，通常可以分成六个阶段：

<box border radius="lg" padding={3} gap={3}>
  <list connector="solid" marker="number" gap={2}>
    <list-item>
      **明确目标**

      先说清楚最终要解决什么问题。
    </list-item>
    <list-item>
      **整理资料**

      找齐文件、图片、链接和必要背景。
    </list-item>
    <list-item>
      **制定计划**

      让 AI 列出步骤、所需工具和可能遇到的问题。
    </list-item>
    <list-item>
      **分步执行**

      一次完成一部分，避免所有事情混在一起。
    </list-item>
    <list-item>
      **检查结果**

      对照要求检查内容、文件和实际效果。
    </list-item>
    <list-item>
      **保存交付**

      把最终成果放到指定位置，更新目录，方便以后继续使用。
    </list-item>
  </list>
</box>

这六步可以用于整理学习资料、解决电脑问题、写工作方案、管理项目，甚至安排一次家庭旅行。

### 为什么要分步？

例如，你要整理 30 个教学视频。

如果只说“把 30 个视频全部整理好”，AI 可能会遗漏视频、混淆课程内容，或者把自己的补充误写成老师原话。

分成步骤后就容易检查：

- 先核对视频清单和标题。
- 再取得字幕或可靠资料。
- 按视频逐节整理。
- 每节加入通俗解释和例子。
- 检查课程原意与现代补充是否区分。
- 保存文件并核对目录链接。

**分步不是为了增加工作量，而是为了让每一步都能检查，发现问题时也容易修正。**

## 四、给每个阶段设定一个看得见的结果

不要只让 AI 说“我做完了”。要让它交出可以检查的东西。

| 阶段 | 应该看到的结果 |
|---|---|
| 明确目标 | 一段清楚的任务说明 |
| 整理资料 | 资料清单、缺失项和来源 |
| 制定计划 | 分步骤计划和风险提醒 |
| 分步执行 | 实际完成的文件、内容或操作 |
| 检查结果 | 检查清单、发现的问题和修正记录 |
| 保存交付 | 保存位置、文件链接和验证结果 |

比如整理一份电脑软件指南，不能只听 AI 说“已经整理好了”。你应该能看到指南文件，打开后内容完整，目录链接能打开，操作步骤也经过核对。

## 五、最值得掌握的四种工作方式

### 方法 1：先计划，再执行

适合：整理大量文件、编写学习手册、规划工作项目、调整电脑设置。

可以这样说：

“先不要直接动手。请先理解我的目标，列出准备采取的步骤、需要的资料、可能的风险，以及最后会交付什么。计划完成后再开始执行。遇到会删除、覆盖、付款、发布或影响账号安全的操作，必须先让我确认。”

这样做的好处是，你能先检查方向，避免 AI 一开始就走错路。

### 方法 2：先做一个小样，再批量完成

适合：整理几十份文档、制作一系列课程笔记、批量生成产品说明。

例如：

“先选第一份资料，按照我要求的格式整理成一个样例。请把标题、结构、语言难度和案例写完整。我确认这个样例符合要求后，再按相同标准处理其他资料。”

为什么不直接全部做？

因为如果第一份的格式就不符合你的要求，批量做完再修改会浪费很多时间。

### 方法 3：让 AI 自己检查一遍

适合：报告、学习笔记、工作方案、文件修改和代码任务。

可以这样说：

“完成后，请不要只告诉我成功。请对照最初的要求逐项检查：有没有遗漏、有没有错误、格式是否符合要求、链接能否打开、文件是否真的保存。如果有无法验证的内容，请明确告诉我，不要把推测说成已经完成。”

这相当于请同事交付前先做一次自查。

### 方法 4：让不同工具各做擅长的部分

适合：需要查资料、分析、执行和长期保存的综合任务。

例如制作一份软件使用指南：

1. ChatGPT 帮你明确问题、整理结构和解释操作。
2. 联网搜索或官方帮助页面提供最新资料。
3. 如果需要在电脑上批量处理文件，再使用有相应权限的 Codex 或其他执行工具。
4. 人工检查关键步骤是否正确。
5. 将确认后的指南保存到 GitHub。

并不是每一步都必须换工具。如果一个工具能可靠完成全部工作，就不必为了分工而分工。

## 六、贯穿全章的真实案例：建设你的 NO1 个人知识库

我们已经在做的 GitHub 仓库，就是一个很好的完整例子。

最初的想法是：把 AI 工具、电脑软件、手机应用、学习资料和个人生活中的有用内容分类保存，以后还能继续补充和查找。

如果只把这个想法告诉 AI，它可能只会给你一些建议。真正落地，需要把它变成一个项目。

### 第一步：明确成果

目标不是“建立一个 GitHub 仓库”这么简单，而是：

- 有清楚的分类。
- 每类资料有统一的整理方法。
- 文件可以长期保存。
- 以后能继续补充和修改。
- 重要修改有记录。
- 资料能被快速找到和复用。

### 第二步：把大目标拆开

| 子任务 | 需要完成的事情 |
|---|---|
| 建立结构 | 设计分类和目录 |
| 整理内容 | 把已有资料变成有用的文档 |
| 建立索引 | 让每类资料都能从目录找到 |
| 检查质量 | 检查文件是否存在、内容是否完整 |
| 后续维护 | 新资料按分类追加，不随意覆盖旧内容 |

### 第三步：先完成一个小范围

先建立五个主要分类，而不是一开始就设计几十个文件夹。

后来根据新的需要，再增加 GitHub 优秀项目收藏分类。

这就是“先做小范围，再逐步扩展”的思路。

### 第四步：逐步完成具体内容

例如《AI For Everyone》课程：

- 先核对课程模块和视频清单。
- 再逐节整理知识点。
- 每节补充生活案例和复习问题。
- 需要时增加现代 AI 发展情况。
- 把笔记保存到对应目录。
- 更新模块索引和学习清单。

### 第五步：检查是否真的完成

不能只看聊天里有没有生成文字，还要检查：

- GitHub 文件是否存在？
- 内容是否能正常读取？
- 目录链接是否正确？
- 学习清单是否与实际文件一致？
- 是否清楚标注哪些内容是课程原意、哪些是现代补充？

这才是一个可以继续使用的知识库，而不是一次性的聊天回答。

## 七、遇到不同任务，怎样拆分工作？

下面列出五种常见情况，可以直接参考。

### 案例 A：解决一个电脑问题

例如 Gemini 安装位置、软件无法登录或 Windows 设置问题。

1. 说明电脑系统、软件名称和版本。
2. 提供错误截图或完整提示。
3. 让 AI 先判断可能原因，按风险从低到高排列。
4. 先尝试不影响文件的检查方法。
5. 每完成一步，观察结果再决定下一步。
6. 成功后整理成可复用的操作说明。

**关键：** 不要一开始就让 AI 删除文件、改注册表或执行不明命令。

### 案例 B：学习一门新课程

1. 先确定课程范围和学习目标。
2. 建立课程目录。
3. 每次学习一节或一个主题。
4. 把知识点解释成通俗中文。
5. 结合生活和工作案例。
6. 用复习题检查自己是否理解。
7. 把学习成果保存起来。

### 案例 C：写一份工作方案

1. 说明工作背景和目的。
2. 提供已有资料和限制条件。
3. 让 AI 先列方案框架。
4. 检查框架是否遗漏关键内容。
5. 再逐部分展开。
6. 检查数据、责任人、时间和风险。
7. 输出可编辑的正式文档。

### 案例 D：整理手机应用

1. 说清楚手机型号和系统版本。
2. 说明想实现什么功能。
3. 提供应用名称、截图或官方链接。
4. 让 AI 区分官方功能和第三方说法。
5. 按步骤操作，每一步确认页面变化。
6. 把有效方法和注意事项保存到“手机应用”分类。

### 案例 E：比较和选择一个产品

1. 明确预算和使用目的。
2. 列出必须满足的条件。
3. 查找当前在售型号和官方参数。
4. 让 AI 整理优缺点和不确定信息。
5. 核对价格、保修和售后渠道。
6. 最后由你决定是否购买。

**关键：** AI 可以帮你分析，但不能替你承担购买决定和付款风险。

## 八、什么时候不应该让 AI 自己继续？

有些事情可以让 AI 自主推进，有些事情必须停下来让你确认。

| 事情 | 建议做法 |
|---|---|
| 整理文字、制作目录草稿 | 通常可以直接推进 |
| 新建普通说明文档 | 确认目标后可以执行 |
| 修改已有重要文件 | 先说明修改内容，保留备份或旧版本 |
| 删除文件、清空文件夹 | 必须先确认 |
| 修改账号、安全设置 | 必须谨慎，关键步骤由本人操作 |
| 付款、购买、预约、公开发布 | 必须由本人确认 |
| 运行来源不明的程序 | 不要盲目执行，先检查来源和风险 |

一个好助手不是事事都问你，也不是事事替你决定。它应该能独立处理安全、明确的日常工作，同时在关键风险点停下来。

## 九、可以直接复制使用的“任务工作单”

下次你有一项复杂任务，不知道怎么交代时，复制下面这段，把括号里的内容替换掉即可。

> **任务名称：** [给这件事起一个简单名字]
>
> **最终目标：** [我希望最后得到什么成果]
>
> **背景：** [为什么要做这件事，谁会使用]
>
> **现有资料：** [我能提供哪些文件、图片、链接或信息]
>
> **限制条件：**
> - 请用通俗易懂的中文。
> - 专业词汇尽量少用，必要时解释。
> - 不要编造事实，不确定的地方明确标出。
> - 不要删除或覆盖重要资料。
>
> **工作要求：**
> 1. 先理解目标并整理工作计划。
> 2. 将任务拆成可以逐项完成的小步骤。
> 3. 先完成一个样例，确认方向正确后再批量处理（适合批量任务时使用）。
> 4. 每完成一个阶段，检查结果是否符合要求。
> 5. 发现资料不足或存在风险时，告诉我具体缺少什么。
>
> **完成标准：** [写清楚怎样才算做好]
>
> **交付方式：** [例如：保存到 GitHub 的某个分类，提供文件链接和检查结果]
>
> **确认边界：** 普通、可逆的整理工作可以按计划推进；涉及删除、覆盖、付款、公开发布、账号安全或其他重大影响的操作，先停下来让我确认。

## 十、本章动手练习：把一个模糊想法变成可执行任务

假设你想做一件事：

“我想把电脑里有用的资料整理好，以后容易找到。”

试着把它补充成一份工作单：

- 最终目标：建立一个清楚的资料目录。
- 现有资料：文档、图片、PDF 和表格。
- 限制：不删除原文件，不随意修改内容。
- 工作步骤：先扫描和列清单，再提出分类方案，确认后整理。
- 完成标准：每份资料都有分类建议，重要文件有备份，整理后可以快速查找。
- 交付方式：生成目录说明和整理记录。

练习重点不是写得多专业，而是让一个不了解你想法的人，也能明白应该做什么。

## 十一、本章小结

1. AI 不会自动读懂你的全部想法，任务要交代清楚。
2. 复杂任务要拆成小步骤，每一步都有明确结果。
3. 先计划、做小样、再批量完成，能减少返工。
4. 交付前要检查实际成果，不能只听 AI 说“完成了”。
5. 不同工具可以分工，但不要为了分工而增加复杂度。
6. 普通工作可以让 AI 主动推进；高风险操作要保留人工确认。
7. 重要成果要保存到长期资料库，而不是只留在聊天记录中。

**最重要的一句话：把目标讲清楚，把工作拆开来，把结果检查好，AI 才能从“会聊天”变成真正帮你做事的助手。**
