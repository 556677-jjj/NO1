# 视频 11：Workflow of a machine learning project（机器学习项目工作流程）

> 模块：Building AI Projects（构建 AI 项目）  
> 主讲：Andrew Ng（吴恩达）  
> 时长：约 7 分钟（课程不同版本略有差异）  
> 整理日期：2026-11-06  
> 依据：公开英文转录辅助核对；中文归纳，非逐字字幕或官方中文讲义。

## 一、本节核心观点

机器学习项目不是“训练一个模型”就结束。吴恩达用智能音箱语音唤醒和自动驾驶汽车识别周围车辆两个例子，说明典型机器学习项目包含三个核心阶段：

1. **收集数据（Collect data）**：准备模型输入 A，以及希望模型输出的正确答案 B。
2. **训练模型（Train model）**：让算法从 A 到 B 的样本中学习规律，并反复迭代，直到表现达到可接受水平。
3. **部署模型（Deploy model）**：把模型放进真实产品或流程中，让用户实际使用。

部署不是终点。真实环境可能出现训练数据中没有覆盖的情况，需要收集反馈数据、维护并更新模型。

## 二、课程案例一：智能音箱识别唤醒词

目标：识别用户是否说出了“Alexa”等唤醒词。

### 第一步：收集数据
- 录制不同人说“Alexa”的音频。
- 也收集说其他词语或普通声音的音频，作为非唤醒词样本。
- 输入 A 是音频片段，输出 B 是“是否说出唤醒词”的标签。

### 第二步：训练模型
- 用带有正确标签的音频样本训练模型。
- 初始模型通常不够好，需要多轮尝试和调整。
- 课程特别举了口音差异：如果训练数据主要是美国口音，产品部署到英国后，可能对英国口音识别不佳。

### 第三步：部署与持续改进
- 将模型放进智能音箱，先供小范围用户使用，再逐步扩大。
- 收集真实使用中识别失败的例子。
- 如果能够合法、适当地获得这些反馈数据，就可用于更新模型、改善不同口音下的表现。

## 三、课程案例二：自动驾驶识别其他车辆

目标：让系统从车辆前方图像中识别其他车辆的位置。

1. 收集道路图像，并为图像中的车辆标注位置，例如画出包围框。
2. 用图像和标注训练模型；初期可能把其他物体误认为车辆，需反复迭代。
3. 在严格安全条件下测试和部署。
4. 上路后可能遇到训练数据覆盖不足的新车型，例如高尔夫球车；收集这些新情况并用于后续维护和更新。

课程强调：自动驾驶等安全关键场景必须把安全放在首位，不能把模型未经验证地直接投入高风险环境。

## 四、通俗理解：模型像一个通过例题学习的学生

假设想让电脑识别照片里有没有猫：

- 先收集大量照片；
- 每张照片都标明“有猫”或“没有猫”；
- 让模型学习照片和答案之间的关系；
- 用没参与训练的新照片检查它是否真的学会；
- 放到真实相册里使用后，继续关注它在哪些照片上容易出错。

如果只给模型看过室内、正面、光线充足的猫照片，它遇到夜间、背影、遮挡或特殊品种时可能判断错误。这就是为什么真实数据覆盖和上线后反馈很重要。

## 五、课程流程图

```text
明确输入 A 和目标输出 B
          ↓
      收集并标注数据
          ↓
        训练模型
          ↓
    测试、评估、反复迭代
          ↓
       小范围部署
          ↓
  监控真实表现与收集反馈
          ↓
     修正数据 / 模型 / 流程
          ↺
```

课程用三个核心词概括：收集数据 → 训练模型 → 部署模型。评估、监控和反馈是把这三个阶段真正连成持续改进闭环的关键。

## 六、2026 年延伸学习：今天的 AI 项目流程有哪些变化？

以下为现代补充，不是课程原话。

### 1. 不一定需要从零训练模型

2019 年课程主要以监督学习模型为例。今天项目还可能直接调用已经训练好的大语言模型或多模态模型，再通过提示词、RAG、工具调用和工作流完成任务。

应先问：现成模型是否已经能完成大部分任务？是否需要接入自己的资料？是否需要微调？只有确实存在明显缺口时，才考虑训练或微调模型。这样通常能降低数据准备、训练和维护成本。

### 2. 评估要前置，而不是等模型训练完再看

在开始开发前，就应准备一组代表真实场景的测试样本，并定义“合格”的标准。例如：
- 语音识别：不同口音、噪声环境下的错误率；
- 图片识别：漏检、误检，以及不同设备/场景下的表现；
- 文档问答：答案是否有依据、引用是否正确、是否承认资料不足；
- Agent 执行：是否完成目标、是否正确调用工具、是否越权、失败时是否及时停止。

对于生成式 AI 和 Agent，测试不只是核对一个固定答案，还要看整个过程和最终任务结果。Anthropic 2026 年关于 Agent 评估的文章强调，应尽早建立评估，让问题在上线前暴露，而不是只在生产环境中被动发现。

### 3. 上线后要监控整个应用，不只是模型

现代 AI 应用往往由多个部分组成：模型、提示词、检索系统、外部工具、数据库和业务规则。回答出错时，原因可能来自任何一个环节。因此需要记录必要的运行信息、监控端到端结果，并持续评估真实使用数据。

### 4. 数据治理和隐私成为项目基础工作

收集数据前要确认来源、使用权限、个人信息处理方式、保存期限和访问控制。不能因为技术上能收集，就默认可以收集或用于训练。对于用户语音、图片、文档和行为记录尤其如此。

### 5. 人工审核仍然重要

对高风险结果或重要动作设置人工审核，例如医疗、金融、招聘、法律建议、付款、删除文件和对外发送信息。自动化程度应与任务风险相匹配。

## 七、旧课程与现代实践对照

| 课程中的传统机器学习流程 | 2026 年扩展 | 仍然成立的原则 |
|---|---|---|
| 收集带标签的数据 | 还可能使用已有模型、企业知识库、合成测试样本和用户反馈 | 数据必须相关、合法、质量可控 |
| 训练模型 | 可能改为调用模型、提示词设计、RAG、微调或组合工作流 | 技术必须适合任务 |
| 迭代训练 | 增加系统级评估、提示词/检索/工具调试 | 不能期待第一次就成功 |
| 部署模型 | 增加灰度发布、权限控制、回滚和人工审核 | 上线前要验证安全性 |
| 收集新数据更新模型 | 持续监控模型、知识库、工具和业务流程 | 上线后仍要维护 |

## 八、应用到个人 GitHub 知识库

如果希望 AI 自动整理你的 GitHub 资料，可以按同样的思路设计：

1. **输入 A**：新上传的 Markdown、PDF、软件说明和学习资料。
2. **目标输出 B**：准确的分类、摘要、关键词、来源和建议存放路径。
3. **准备测试样本**：先挑选几十份已有文件，人工确认正确分类，作为检验基准。
4. **小范围试用**：先让 AI 给出分类建议，不直接移动或删除原文件。
5. **评估**：检查分类准确性、遗漏率、摘要是否忠于原文、引用链接是否正确。
6. **部署与维护**：确认效果稳定后再扩大使用；保留版本历史，遇到不确定情况交给用户确认。

这个例子说明：AI 知识库项目不一定需要自己训练模型。可以先用现成模型 + 搜索/RAG + 明确规则，再根据实际效果决定是否增加更复杂的自动化。

## 九、关键术语

- **Input / Output（输入/输出）**：模型接收的信息，以及需要产生的结果。
- **Label（标签）**：数据样本对应的正确答案，例如图片是否有车辆。
- **Training（训练）**：利用样本调整模型，使其学会输入与输出之间的规律。
- **Iteration（迭代）**：根据测试结果反复调整数据、模型或系统。
- **Deployment（部署）**：将模型或 AI 应用放入真实产品或工作流程。
- **Feedback data（反馈数据）**：真实使用过程中发现的新样本、错误和用户反馈。
- **Data drift / Distribution shift（数据漂移/分布偏移）**：上线环境的数据与训练或测试数据出现差异，导致表现下降。
- **Evaluation（评估）**：通过测试样本和指标判断系统是否达到目标。

## 十、复习题

1. 吴恩达总结的机器学习项目三个核心步骤是什么？
2. 为什么语音识别模型在美国口音上表现好，不代表在英国口音上也一样好？
3. 自动驾驶案例为什么需要特别强调安全测试？
4. 今天调用现成大模型时，为什么仍然需要测试集和上线监控？
5. 如果 AI 要自动整理个人资料库，哪些动作应该先交给人确认？

### 答案提示

1. 收集数据、训练模型、部署模型。
2. 因为真实用户的口音分布可能与训练数据不同，模型可能无法很好泛化。
3. 错误可能造成现实人身伤害，部署必须经过严格验证和风险控制。
4. 模型可能产生错误，检索、提示词、工具和数据也可能出问题，真实场景会变化。
5. 删除、覆盖、批量移动、对外分享等高影响操作应设置确认点。
