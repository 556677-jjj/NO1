# GitHub 仓库维护

## 开始前
1. 确认目标仓库和用户要求的范围。
2. 读取仓库可见性、根目录 README 和相关目录树。
3. 区分公开仓库 NO1 与私有仓库 NO2；不要把两者混为一谈。
4. 检查现有文件，避免重复创建或无意覆盖。

## 维护步骤
1. 先检查，再提出或执行范围内的整理。
2. 文件名清楚、稳定；重要说明优先使用 Markdown。
3. 新增目录时放入 README，解释用途、内容边界和安全注意事项。
4. 修改现有文件前先读取当前内容和版本信息。
5. 不删除文件、不重写重要原件、不批量移动内容，除非用户明确授权。
6. 修改后重新读取文件或检查 GitHub 树，验证实际提交结果。
7. 更新相关索引和内部链接。

## 安全边界
- NO1 仅存放适合公开分享的内容。
- NO2 存放私人工作与未公开内容；保持 Private。
- 跨仓库复制、公开发布、删除、修改可见性和覆盖重要资料必须先确认。
- 不把密码、验证码、API 密钥、私钥或恢复码写入仓库。
- 不把“已调用写入工具”当作成功；必须核验文件内容和仓库状态。

## 完成交付
报告：目标仓库、文件变更清单、核验结果、尚未完成事项和文件链接。
